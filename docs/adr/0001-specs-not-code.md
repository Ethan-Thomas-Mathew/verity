# 0001: Agents write declarative test specs, not code

## Decision
The planner returns JSON test specs (`src/verity/runners/specs.py`): HTTP steps with expected status and fields, and UI steps from five actions. Verity's runners execute them.

## Options considered
- **Let the model write pytest or Playwright code and run it.** Most flexible, and what many demos do. But running model-written code means a confused or manipulated model can do anything the process can: read files, call other hosts.
- **Declarative specs (chosen).** Pydantic validates every spec before it runs. Paths must be relative, so requests only reach the target app.

## Trade-off
Specs cannot express everything code can (loops, custom assertions). For requirement-level functional tests that has not been a limit. Code is still available: approved specs export to a pytest file (ADR 0008), generated by Verity, not by the model.
